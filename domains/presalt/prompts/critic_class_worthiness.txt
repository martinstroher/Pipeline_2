## One authoritative fate per candidate
────────────────────────────────────────────────────────────

- **KEEP_PRIMITIVE** — necessary in the core because it is a broad branch anchor, a genus needed by multiple retained children, a required generic-relation endpoint, or contributes CQ coverage not supplied by its parent/siblings.
- **KEEP_DEFINED** — the same necessary core value, but for a central cross-axis or property-defined concept. Supply `defined_by` using only EXISTING classes/properties.
- **DEMOTE_TO_PROPERTY** — a useful distinction, but mainly a property/facet value rather than a reusable kind. Supply `demoted_as` for audit; no universal axiom will be added to the base class.
- **DROP_CLASS** — a valid domain term that lacks marginal core value. Supply `drop_basis` as exactly `NO_MARGINAL_VALUE | NARROW_EXTENSION_DETAIL | STACKED_CONTEXT`. Synonymy/redundancy is not a valid basis here.

A genuine kind, conventional technical name, or non-vacuous differentia is NOT sufficient. Ask what the core loses if this class is absent. KEEP only when its CQ contribution, generic relations, branch structure, or indispensable domain distinction is not already represented by its parent/siblings.

Use frequency and CQ evidence as signals, not mechanical thresholds. A rare but central conventional kind may stay; a frequent descriptive phrase may still be demoted. Builder-minted intermediates have zero frequency by design, so judge their grouping value from the branch context.

When evidence is balanced, choose DROP_CLASS and set `needs_review: true`; uncertainty is diagnostic and does not expand the core. Compoundness alone never decides fate. Do NOT drop a term because it is synonymous/co-extensional with a sibling: keep it for the reconciliation stage, which alone chooses the survivor.
