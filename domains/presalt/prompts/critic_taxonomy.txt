## Three structural probes — RUN ON EVERY TAXONOMY ROW
────────────────────────────────────────────────────────────

### Probe 1 — Genus / differentia separability
Read the NLD as Aristotelian form `X is a Y that <differentia>`.
- Does the genus `Y` stand alone as a real kind (independently nameable, not a mixin)?
- Is the `<differentia>` a **contingent** property of `Y` (i.e., `Y` could exist without it and still be a `Y`)?
If yes to both → genus/differentia is clean.
If the differentia is **necessary** to be a `Y` → the row may be a vacuous restatement of the parent.

### Probe 2 — BFO-bucket categorisation of the differentia
Classify the differentia text into exactly one bucket:
`Quality | Disposition | Role | Site | Process | TemporalRegion | None`
- **Quality** — an inhering property that is simply present, needing no further process to be realised (colour, viscosity, mass)
- **Disposition** — an internally-grounded capacity realised only in a process (soluble, brittle, elastic, conductive). A **Function** (a capacity the bearer exists to perform) goes here too.
- **Role** — an externally-grounded function, holding only by the bearer's relations to other entities (husband, student, employee)
- **Site** — a place or region the bearer occupies
- **Process** — an unfolding occurrent the bearer participates in
- **TemporalRegion** — a span or instant of time
- **None** — the differentia is itself an essential structural feature (genuine subkind)

Anything other than `None` → **mixin candidate**: the differentia is a separate BFO entity inhering in / realised by / occupied by / participated in the bearer, not a subkind discriminator.

### Probe 3 — Counterfactual relational rewrite
Try to restate the row as `<parent> + <relation> some <differentia-as-entity>` (a generic BFO verb such as `has_quality`, `has_disposition`, `has_role`, `located_in`, `participates_in`, `occupies_temporal_region`).
- If such a rewrite produces a sentence with the **same truth conditions** as the NLD → confirmed mixin; the IS-A row is wrong and a relation should carry the meaning.
- If no relation can capture it cleanly → the term is a genuine subkind; KEEP.

## Seven checks (taxonomy rows)
────────────────────────────────────────────────────────────

1. **OntoClean parent–child edge (use the parent's definition above).** Check the `term → parent` edge:
    - **Rigidity** — an anti-rigid parent must not subsume a rigid child. ~R: instances can stop being of the kind while still existing (`Student`, `Employee`); +R: they cannot (`Person`, `Organism`). Violation (parent ~R **and** term +R) → REPARENT onto a rigid genus.
    - **Dependence** — a dependent parent must not subsume an independent child. +D: every instance requires a separate entity (`Husband` needs a spouse, `Employee` needs an employer); -D: self-standing. Violation (parent +D **and** term -D) → REPARENT onto an independent genus.
    - **Identity (advisory)** — record the term's `identity` sign, but **never REPARENT on identity alone**. Only *note* in `reason` when both parent and child lack an identity criterion (`-I ⊑ -I`, a vague-umbrella stack), and **only when the child is a substantial sortal** (an object / material-entity kind). On Quality / Role / Disposition / Process / TemporalRegion branches `-I` is normal and correct — do not flag.
   Name the violated sign in `reason`; if you cannot name a better genus for a rigidity/dependence violation, KEEP.
2. **Quality-as-class.** Does the NLD describe a property the bearer **has** (colour, density, weight) rather than something the bearer **is**? If yes → mixin; either DROP_AS_MIXIN or KEEP with an emitted `inheres_in` restriction on the child.
3. **Role-as-class.** Does the NLD describe a function the bearer plays in a system (`acts as a barrier`, `serves as a container`, `provides support`)? If yes → REPARENT under `role` (the bearer remains a separate class).
4. **Mixin via Probes 1–3.** If all three probes flag the row → DROP_AS_MIXIN.
5. **Vacuous restatement (parent-collapse).** Does the term merely restate its own **parent** — the Probe-1 differentia is *necessary* for the genus, so the term adds nothing and is extensionally equal to its parent? Use the parent's definition above to confirm. If yes → DROP_AS_REDUNDANT, `survivor` = the parent.
6. **Proper-noun instance.** Is the term a proper noun naming exactly one thing (a person, a place, a specific event, a named time period)? → CONVERT_TO_INSTANCE with a `target_class`.
7. **Interface / analytical-framework as class.** Is the term a methodology, model, framework, classification scheme, or measurement unit dressed up as a domain entity? → DROP_AS_MIXIN.

**Precedence — if several checks fire on one row, apply the first matching verdict in this order:** proper-noun (6 → CONVERT_TO_INSTANCE) → framework (7 → DROP_AS_MIXIN) → role (3 → REPARENT under `role`) → quality/disposition mixin (2, 4 → DROP_AS_MIXIN) → OntoClean rigidity/dependence edge (1 → REPARENT) → vacuous restatement (5 → DROP_AS_REDUNDANT) → else KEEP. (E.g. `Student` is both a role and an edge violation → REPARENT under `role`.)

## Five verdicts (taxonomy rows)
────────────────────────────────────────────────────────────

- **KEEP** — passes all probes / checks, parent is correct.
- **REPARENT** — term is real but mis-parented. Move it only when the term's NLD and/or its relation context clearly justify a better genus.
    - Provide `new_parent`. Cite the evidence in `reason`: a relation `id` from the context, a probe result, or the NLD phrase that fixes the genus.
    - **Lateral moves to arbitrary siblings are discouraged** — the new parent should be a better genus justified by Probe 2 / Probe 3, not a sideways guess at the same depth.
    - If you cannot justify the move from the NLD or relations → KEEP, do not bluff.
- **DROP_AS_MIXIN** — the differentia is a separable BFO entity (Probe 2 bucket ≠ None), not a subkind. Cite which bucket. **MUST carry `carried_by`** — the BFO entity the differentia encodes, recorded as `{{"property": "has_quality", "filler": "RedColour"}}`. The term is **removed**; `carried_by` is logged to the audit trail for traceability (it is not re-emitted as an axiom).
- **DROP_AS_REDUNDANT** — the term vacuously restates its **parent** (Probe 1 / Check 5): it adds no differentia beyond its genus, so it is extensionally equal to its parent. Set `survivor` to the parent term.
- **CONVERT_TO_INSTANCE** — the term is a proper-noun individual (names exactly one thing: a person, place, organisation, named time period, specific event). MUST carry `target_class`:
    - Choose the single best fit from the **Allowed target classes** list above — the most specific listed class that still correctly types the individual (e.g. a named time period → `temporal region`; a named place / region → `site`; a named physical object → `object`).
    - ONLY if no listed class is specific enough AND a more precise kind is clearly warranted, set `target_class` to a NEW class name (e.g. `Painting`) and add `mint_parent` naming the listed class it falls under.

## Abstention rules (when to default to KEEP)
────────────────────────────────────────────────────────────

A. **Vocabulary disagreement.** Do NOT drop a row just because you would phrase it differently. KEEP unless you can cite a probe or a check.
B. **Upper-ontology disagreement with the source taxonomy.** If a term sits under a category root you would not have chosen but a real argument exists either way → KEEP. REPARENT only when the NLD or relations clearly justify a better genus.
C. **Named individuals.** Do NOT drop named individuals (<<examples_critic_named_individuals>>) unless clearly out of scope. Prefer CONVERT_TO_INSTANCE.
