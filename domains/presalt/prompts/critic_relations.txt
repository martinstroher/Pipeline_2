## Three verdicts (relation rows)
────────────────────────────────────────────────────────────

- **KEEP** — property and filler are correct; evidence is non-vacuous.
- **DROP** — vacuous (`X has_part X`), tautological, or fundamentally wrong (e.g., a process bearing a quality of a continuant).
- **FIX** — supply `new_property` and/or `new_filler`. Use FIX **only** when:
    - the **property is genuinely wrong** — it is not a real BFO/RO property, or it is BFO-invalid for the subject/filler metatypes; **or**
    - the **filler is wrong** (points at the wrong entity); **or**
    - a **taxonomy decision requires re-expression** (e.g. the subject was REPARENTed under `role` → restate via `has_role`).
  Do **NOT** FIX merely because a property is absent from the menu, to specialise/genericise parthood, or to reword. When replacing a wrong property, pick the closest menu target; if none fits and no role-detour works, attach a `mint` block (see next section).

For every own relation, also set **`relation_scope`**:
- `generic` — true of the class/kind itself; safe to emit as an OWL class axiom.
- `corpus_context` — true only in the papers' study area, dataset, basin, field, or examples; useful evidence but NOT a universal class axiom.
- `individual_fact` — a factual relation involving a named individual rather than a generic class restriction.

Scope is independent of property correctness. A relation can be semantically plausible but still `corpus_context` and therefore excluded from generic OWL class restrictions.

## Property minting (last resort)
────────────────────────────────────────────────────────────

Prefer existing properties and the role-detour pattern (`has_role some <NewRole>`) over minting. Only mint a new property when **no menu entry + no role detour** captures the relation.

Minting rules — a `mint` block on a FIX must satisfy ALL:
- **Generic verb name** — `produces`, `secures`, `contains`, `yields`. **Forbidden:** predicate+object names (`produces_offspring` is wrong — the filler class carries the object).
- **subPropertyOf parent** — must be the name of a property already in the menu (e.g., `has_participant`, `located_in`).
- **Domain / Range** — metatype tokens (e.g., `MaterialEntity`, `Process`, `Role`).
- **Justification** — one sentence explaining why no existing property fits.

## Abstention rules
────────────────────────────────────────────────────────────

A. **Vocabulary disagreement.** Do NOT FIX a relation just because you would phrase it differently, or to match the menu. KEEP unless the property is genuinely wrong or the filler is wrong.
B. **Ancestor rows.** Rows with `chain_role: ancestor` are CONTEXT ONLY. Do not emit any edit for them.
